# Vault user profile

> **GENERATED / READ-ONLY.** Do not edit this file directly. Use the Memory
> plugin or the `notemd memory` proposal workflow. A direct filesystem edit is
> drift, not human approval.

This projection is the canonical, machine-readable answer to "whose vault is
this?" and contains stable facts about that person. A new vault starts
deliberately unclaimed.

## Owner activation

Use the Memory plugin's owner-claim form. It creates an immutable proposal and
an approval event bound to the exact owner actor and names. The owner is active
only when `owner.actor` is one stable `human:<id>`, `owner.names` is non-empty,
and `owner.confirmed: true`. Until then an Agent must treat the owner as unknown
and must not create owner Tasks.

## Stable profile

Keep only durable facts that help an Agent work with the owner. Every projected
entry is one atomic claim. Review state, evidence type, certainty and Agent
behavior are deliberately separate:

```text
- <stable profile fact>
  status:: active | pending | revoked
  priority:: critical | high | normal | low
  polarity:: positive | negative | neutral
  epistemic-status:: owner-stated | source-supported | inferred | contested | unknown
  certainty:: high | medium | low | unknown
  agent-guidance:: <one executable sentence for an Agent>
  avoid-error:: <forbidden inference or action; required for unsafe/uncertain entries>
  id:: <UUID v4>
  revision:: <positive integer>
  proposal:: <proposal UUID>
  approved-by:: human:<owner-id>
  approved-at:: <RFC 3339 datetime>
```

`pending` is not a confirmed fact. `approved-by` records the owner's decision to
remember a claim, not objective proof. `positive` means follow a preference;
`negative` means avoid a mistake or boundary violation; `neutral` is context.
The projection deliberately contains no inline citations, footnote definitions,
or per-entry `source::`. An Agent resolves `proposal::` to the immutable
candidate and verifies its `sources`, or asks the owner, whenever evidence or
certainty is unknown. Inferred claims can never have high certainty.

## Controlled maintenance

- No human or Agent edits this projection directly.
- An Agent may inspect with `notemd memory list/show/suggest` and may create only
  an immutable candidate with `notemd memory propose`. A proposal never changes
  active memory by itself.
- The confirmed owner approves or rejects the exact candidate diff in the
  Memory plugin. An Agent may record an approval from the current conversation
  only after the owner explicitly names the proposal/diff; it must pass the
  dedicated human-confirmation flag and the displayed candidate
  `--proposal-sha256`, and must never infer or batch approval.
- A deliberate owner click on **Confirm** for a fact or **Approve** for a
  displayed proposal is the approval itself and writes the SHA-bound decision
  immediately; do not add a second confirmation step.
- Owner identity, names, authority, permissions and action-sensitive
  preferences are always high-sensitivity, one-at-a-time decisions.
- Deletion is a reversible `revoke` event, not physical history removal.
- External edits trigger drift and block writes until the user imports the
  difference as a proposal or restores the approved projection.
- Do not put daily events, reminders, credentials, tokens, private keys or
  secrets here.
