# Shared long-term memory

> **GENERATED / READ-ONLY.** Do not edit this file directly. Use the Memory
> plugin or `notemd memory propose`; direct changes are drift, not approval.

This is the compact durable projection, not a transcript, activity log, Task
list or dumping ground.

## Active memory

Every claim has one stable ID and one current revision. Safety fields stay next
to the claim so search results preserve their meaning:

```text
- <durable fact, constraint, or decision>
  status:: active | pending | revoked
  priority:: critical | high | normal | low
  polarity:: positive | negative | neutral
  epistemic-status:: owner-stated | source-supported | inferred | contested | unknown
  certainty:: high | medium | low | unknown
  agent-guidance:: <one executable sentence for an Agent>
  avoid-error:: <forbidden inference or action; required for unsafe/uncertain entries>
  id:: <UUID v4>
  revision:: <positive integer>
  proposal:: <proposal UUID>
  approved-by:: human:<owner-id>
  approved-at:: <RFC 3339 datetime>
```

`status:: pending` is never a confirmed fact. `approved-by::` means the owner
approved remembering the claim, not that external reality proved it. The
projection deliberately contains no inline citations, footnote definitions, or
per-entry `source::`. Resolve `proposal::` to the immutable candidate under
`/inbox/memory-candidates/` and inspect its `sources`, or ask the owner, for
`unknown`, `inferred`, or `contested` material.
`polarity:: positive` means follow the preference or principle when relevant;
`negative` means actively avoid the specified error; `neutral` is context.
`priority` affects attention only and never grants authority, permission, or
approval. `critical` is reserved for identity, privacy, authority, and
real-world action risk.

## Revoked memory

Normal deletion is `status:: revoked`. Immutable proposal and decision events
retain the prior revisions, so the system can explain and rebuild history.
Superseding or merging produces one new active revision and explicit revoke
events; it never leaves two current truths.

## Controlled maintenance

- No human or Agent edits this projection directly.
- Agent changes are immutable one-claim candidates under
  `/inbox/memory-candidates/`; they stay pending until the owner approves the
  exact diff and candidate SHA-256. CLI decisions must pass the `sha256` from
  `notemd memory show <proposal-id> --json` as `--proposal-sha256`.
- Approval and rejection are immutable one-event Markdown files under
  `/memory/events/`. Agent provenance cannot masquerade as `human:` approval.
- A deliberate owner click on **Confirm** for a fact or **Approve** for a
  displayed proposal is the approval itself and writes the SHA-bound decision
  immediately; do not add a second confirmation step.
- Tasks and reminders belong in `/inbox/tasks/`; daily or episodic detail
  belongs in the vault's daily-note system. Raw transcripts stay with sources.
- Permission, authority, commitment and other action-sensitive claims require
  explicit human confirmation before becoming active memory.
- Direct external edits trigger drift and are never silently accepted or
  overwritten. Unknown versions, hash mismatches and stale base revisions fail
  closed for repair.
- This file syncs with the vault. Do not put secrets here or expose it in
  shared, public, or external contexts unless the owner authorizes that use.
