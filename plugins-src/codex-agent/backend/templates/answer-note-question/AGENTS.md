# 手记答疑(codex-agent)

回答手记(`.note.md`)里 `status:: open` 的问题。**只回答问题,不改别的。**

`AGENTS.md` 是 harness 中立的公共约定名 —— 你现在读的这份是本任务的,
vault 根目录还有一份是全局的。两份都算数。

## 你写在哪儿

只写这篇手记的 `.note.md`。**源 markdown(`.md`)永远不要动。**

## 怎么写一条答复

在被回答的那个 `type:: question` 节点**下面**加一个子节点:

```
- ✦
  type:: answer
  by:: codex/<本次运行署名中的模型名>
  created:: 2026-08-17T10:00:00Z
```

答复正文放在**紧跟其后**的围栏里。围栏必须和 `- ` 在同一行开头:

```
- ```
  这里是答复正文。
  ```
```

三条硬规矩,每条都踩过坑:

1. **围栏必须紧跟 `- `**。写成 `- ✦` 换行再放围栏,解析器看不见它 ——
   卡片不显示,而且**每次保存都会掉一条答复**。
2. **绝不手写 `✦`**。`type:: answer` 本身就是署名,渲染时前端会自己加。
   手写会把围栏撑坏。
3. **`by::` 一定使用运行 prompt 的「本次运行署名」**(形如
   `codex/<模型名>`),绝不是 `human:` 开头，也不要写 `codex/default`。
   `✦` 代表 AI 写的、`●` 代表人想的 —— 这条线不能混。

## 状态机

答完把那个问题节点的 `status::` 从 `open` 改成 `answered`。

**只许 `open → answered`。** `closed` 和 `adopted` 是人的判断,你不碰。

## 答不出来的时候

说答不出来,并说清缺什么。把 `status::` 留在 `open`。
编一个像样的答案比留着问题坏得多。

## 长答案

超过约 400 字就写进本任务目录的 `output/<日期>-<短标题>.md`,
手记里的答复只留三五句摘要 + 一个 `[[wikilink]]` 指过去。

长答案文件必须带 OKF frontmatter:

```
---
type: Answer
title: "标题"
generated: { by: codex/<本次运行署名中的模型名>, at: 2026-08-17T10:00:00Z }
---
```

## 沙箱

你的 bash 和文件工具跑在沙箱里。`[sandbox: file access denied …]`
是策略,不是命令写错了 —— 换个在允许范围内的做法,别反复重试。
