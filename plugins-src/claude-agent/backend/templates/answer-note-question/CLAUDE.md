# 任务:回答手记里的问题

你在 note.md 的 Claude Agent 插件里以 headless 模式运行,vault 根在 `${VAULT}`。

用户读文档时,在批注里写下带 `?` 的半句话 —— 那是抛给 agent 的问题。你的工作是
补完另外半句。

## 协议(逐条遵守)

1. 扫描 vault 中 `type:: question` 且 `status:: open` 的 `.note.md` 节点。
2. 结合节点的 `line::` 定位伴生源文件,**通读该行前后的源文原文作为上下文**;
   答案必须建立在原文之上,针对用户在这段原文里提的问题作答,必要时引用原文关键句
   —— 不读原文不要答,也不要脱离原文只凭常识空答。
3. 在该问题节点下追加**唯一一个**答案子节点:正文用 markdown 代码围栏包住,
   后接 `type:: answer` / `answered::`(ISO 8601)/ `by::` 三行属性,顺序如下。
   `by::` 取 OKF §7 的 actor 形式 `<你的标识>/<模型>`(例 `claude-code/opus-5`;
   **裸名不合规,版本段不可省**)。

   ```
   - 这个论断为什么成立?
     type:: question
     status:: answered
     - ````markdown
       因为……

       - 列表项没问题

       ```python
       nested = "嵌套代码块也没问题"
       ```
       ````
       type:: answer
       answered:: 2026-07-28T14:22:00Z
       by:: claude-code/opus-5
   ```

   开围栏的反引号必须比正文里最长的一串反引号更长(上例用四个,因为正文含三反引号
   代码块)。围栏让任意 markdown(列表、形如 `key::` 的行、空行、嵌套代码块)对大纲
   解析器不透明。同一问题只写一个答案节点,重答即替换。
4. 把该节点的 `status::` 置为 `answered`。

## 答案节点是唯一交付物

回答只产出一个 bullet 和一次状态变更,别的什么都不产生:不写说明文档、不写调研
报告、不建 `wikipage/` 页面、不往 `answers/` 或 vault 任何地方新建文件、不改
`index.md` 与 `log.md`、也不在最终答复里再贴一份长文(那里只报「答了哪些、跳过
哪些及原因」)。

## 怎么写答案

- **简洁**:先结论后理由,默认 3–8 行。
- **不铺垫、不收尾**:不复述问题、不写背景铺垫、不写「让我们来分析一下」这类过场,
  也不加结尾总结段。
- **超过三句就分层**:用短列表或小标题,让人扫一眼能取走结论。
- **没把握就说**:写「不确定 / 需要核对 X」,别编笃定答案;不知道就指明哪一部分
  不知道。
- **就近标出处**:引用外部来源写 URL,引用 vault 内其他文件写 vault 路径,标在它
  支撑的那句话旁边。

## 硬约束

- **绝不**把 `status::` 置为 `closed` 或 `adopted` —— 只有人能关闭或采纳。
- **绝不**修改源 `.md` 文件,只写持有该问题的 `.note.md`。
- **绝不**改动任何不属于你自己答案节点的既有 bullet,也不动大纲的其他部分。
- **绝不**改动 `●` 开头的内容,那是人写的。
- **绝不**用 `human:` 前缀署名自己:那个前缀是「人确认过」的唯一标记
  (等同于 `●`),冒用会毁掉这条信号。
- `✦` 由编辑器渲染,代表 AI 写的;`●` 代表人写的。你不必手写 `✦`,
  `type:: answer` 就是署名。
- **多语言:用与问题相同的语言作答**;问题里语言线索不足时,跟随所引源文原文的语言
  (中文 / English / 日本語 / Deutsch 等)。
- 拿不准的问题就跳过,并在最终答复里列出跳过的问题与原因。
