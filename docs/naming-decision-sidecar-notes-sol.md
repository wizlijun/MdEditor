# note.md 功能命名决策：手记（Sidecar Notes）

> gpt 5.6 sol

```
zh-CN  手记
en     Sidecar Notes
ja-JP  サイドノート
de-DE  Randnotizen 
```

## 一、命名对象

“手记”不是普通的 Markdown 笔记，而是一份陪伴源文档存在的个人记录。

当用户阅读或批注某个源文件时，note.md 会将源文件镜像进 vault，并创建一份与其配对、独立保存的 `.note.md`文件。它具有四个核心特征：

1. 与源文档一一配对，并随源文档存在。
2. 与原文分开保存，绝不混入 AI 生成的文字。
3. 用户可记可不记，是否留下内容完全由人决定。
4. 专门保存用户的判断、意图、线索和想法。

它真正珍贵的地方，不是“写在文档旁边”，而是“由谁在什么时刻留下了怎样的判断”。

## 二、命名目标

中文名称需要同时满足：

- 简单易认，能够自然说出口。
- 两到四字，适合出现在按钮、标签和说明文案中。
- 能体现这是用户本人留下的内容。
- 能暗示它与原文相伴，但不与原文混写。
- 有一定品牌辨识度，同时不增加理解负担。

## 三、探索过的命名方向

### 1. 伴生笔记

“伴生”能够表达两份文件配对存在，但“生”字发涩，容易让人联想到伴生矿、伴生关系等技术或生物学概念。

它描述了系统结构，却没有表达人的思考为何珍贵，因此被放弃。

### 2. 旁记

“旁记”很容易理解：在原文旁边留下记录。

但它的问题也很明显：

- “旁”和“记”都是说明性用字，组合后缺少声音上的余味。
- “旁”容易产生旁支、附属、次要的感觉。
- 它只说明笔记的位置，没有说明笔记属于谁。

而在 note.md 的理念中，人的判断并不是附属数据，反而可能是整篇文档中最有价值的部分。

### 3. 影子笔记

“影子”能够很好地表达陪伴和配对关系：源文档走到哪里，笔记就跟到哪里；两者紧密相关，却不是同一个对象。

它有画面，也容易记忆。但“影子”仍可能让人觉得这份笔记是原文的复制品或附属物，没有充分强调人的主动判断。

### 4. 对影

“对影”取意于“举杯邀明月，对影成三人”。

“对”既可以表示用户面对原文，也暗合两份文件配成一对；“影”则代表阅读后留下的思想痕迹。

这个名字诗意和品牌感都很强，但第一次接触时不容易知道它是一种笔记，更适合作为品牌文案或概念名称，而不是高频功能名。

### 5. 朱批、圈阅与题跋

传统语境提供了另一条重要线索：

- 皇帝在奏折上留下的意见称为“御批”或“朱批”。
- 现代公文处理中，领导阅读并作出意见称为“阅批”；以画圈或签名表示已阅、同意，称为“圈阅”。
- 书画作品中，后来者留下的评论、鉴定和观感称为“题跋”。

这些内容之所以珍贵，不是因为写在原作旁边，而是因为它们记录了特定人物在特定时刻作出的判断，并为原作增加了身份、来历和历史。

这一轮探索确认了命名的真正重点：不应只强调“旁边”，还要强调“本人留下”。

但“朱批”过于帝王化，“圈阅”偏公文流程，“题跋”理解门槛较高，因此没有直接采用。

### 6. 笔记

“笔记”是理解成本最低的名称，但它只是一个通用品类。

它无法区分普通 Markdown 文件与这种特殊的配对笔记，也没有表达 AI 文字与人的文字之间的边界。直接使用“笔记”，会失去一次建立产品概念的机会。

### 7. 手记

“手记”是最终选择。

它是一个自然、成熟、人人认识的中文词。“手”不必限定为手写，而是代表亲手、亲历和本人留下；“记”则明确说明它是一份记录。

它同时具备几个优势：

- 读写自然：“创建手记”“打开手记”“本文手记”都能直接使用。
- 强调归属：这是由用户本人留下的内容。
- 区分 AI：原文可以生成，手记必须来自人的判断。
- 不把人的思考称为旁支或附属。
- 简短稳定，不需要依赖典故才能理解。

“手记”不能单独解释与源文档配对的技术结构，但这一点可以由英文名、首次说明和界面行为共同完成，不需要把全部含义压进两个汉字。

## 四、最终决定

中文名：**手记**

英文名：**Sidecar Notes**

技术文件：**`.note.md`**

中文名与英文名不做逐字翻译，而是各自承担不同职责：

- “手记”强调内容的来源和价值：这是人亲自留下的判断。
- “Sidecar Notes”强调产品结构：它像边车一样与源文档配对，独立存在并随之同行。

两者结合后，完整表达了这一功能的核心：

> 一份跟随原文、独立保存、只承载你的判断和想法的个人笔记。

## 五、推荐文案

功能定义：

> 手记，是一份与原文配对、独立保存的个人笔记。

品牌表达：

> 原文可以由 AI 写，手记只能由你写。

界面用语：

- 为本文创建手记
- 打开手记
- 本文还没有手记
- 手记与原文分开保存
- 删除手记不会影响原文

最终名称“手记”没有着重描述它位于哪里，而是回答了更重要的问题：

> 这是谁留下的？

答案是：这是你的手记。
