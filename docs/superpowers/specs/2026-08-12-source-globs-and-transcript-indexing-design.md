# 原始资料模式 + 转写收录 + 权重设置 —— 设计

> 类型:设计规格 · 日期:2026-08-12
> 前置:`2026-08-11-md-origin-tiering-design.md`(md 分级,已随 v6.812.1 发布)
> 遗留清单:`docs/superpowers/plans/2026-08-12-search-tiering-followups.md`

## 0 · 一句话

把「原始资料」从**猜**(缺 frontmatter 就算)改成**指定**(你给的通配模式),顺带让指定范围内的 `.srt`/`.txt`/`.vtt` 也能被搜到,并把分层权重交给用户。

## 1 · 为什么

v6.812.1 上线的分层有两处名不副实:

- **「原始资料」这一层名不副实。** 它同时装着两拨性质不同的东西:镜像目录里的外部文档(确实是资料),和**任何缺 frontmatter 的文件**(真实状态只是「没人声明过这是谁写的」)。后者被贴上「原始资料」是一个**肯定句形式的错误声明**,而且伤到设计意图 —— 设置页那句提示要用户看着「原始资料偏高」去补 frontmatter,可标签本身却在告诉他「这些是资料」。
- **真正的原始资料认不出来。** 用户的原始材料是**成批放在指定目录里的**(ebook 导出、字幕转写、博客原文),不是靠「缺 frontmatter」这个特征。而这些目录里同时还混着 AI 生成的摘要。

还有一处更硬的缺口:**`.srt`/`.txt` 根本不在索引里**。`scan.rs` 的 `is_indexable` 只有一行 `if !rel.ends_with(".md")`,所以体量最大的一批原始材料(转写稿、纯文本)在搜索里完全不存在,只能靠 `rg` 找。

## 2 · 范围

**做:**
- 一组「原始资料模式」(glob),同时决定**收录范围**与**分层归属**
- 新增第 4 层 `unlabeled`(未标注)
- `.srt` / `.vtt` / `.txt` 解析器,仅在命中模式时收录
- 四层权重可在设置中调整
- 设置页的模式编辑器(粘样例路径生成候选 + 实时命中数)
- `origin:unlabeled` 过滤器,以及从统计跳过去的行动入口

**不做:**
- 其余三个乘数(人工签字 ×1.1、批注 ×1.2、日期新近度)不进设置 —— 那些是文档属性,不是来源分层
- 不做正则、不做花括号展开(见 §4.1 的理由)
- 不为 `.srt`/`.txt` 做专门的编辑器 —— `tabs.svelte.ts` 已有「未知扩展名 + 无插件认领 → 当纯文本打开」的兜底

## 3 · 分层规则(规范性,有序,首次命中即止)

在既有规则表上改两条、加一层。**顺序是规范性的,改顺序就是改行为。**

| # | 判定 | 结果 |
| --- | --- | --- |
| 1 | 路径以 `.note.md` 结尾 | 你写的 |
| 2 | `generated.by` 存在 | `human:` 前缀 → 你写的;否则 → AI 产出 |
| 3 | `verified` 里有 `human:` 签字 | 你写的 |
| 4 | `type` 在 `CONCEPT_TYPE` 中已注册 | 按类型映射表 |
| **5′** | **命中任一原始资料模式** | **原始资料** |
| **6′** | **没有 frontmatter**(且未命中模式) | **未标注** |
| 7 | 其余(有 frontmatter,类型未注册) | AI 产出 |

**规则 5′ 取代原规则 5。** `syncDir` 特例取消 —— 它做的事模式完全能表达,而保留它意味着同一件事有两套并行机制(一个设置 + 一个 `ScanOptions` 字段 + 一份独立的 `meta` 盖章)。迁移见 §5.2。

**规则 6′ 是这次的核心修正。** 缺 frontmatter 不再等同于原始资料,而是老实说明「无人声明」。

**规则 2/4 仍在 5′ 之前,这是刻意的**:指定目录里的 AI 摘要仍判 AI 产出。既有测试 `a_registered_type_beats_the_mirror_dir` 覆盖这个顺序,需改名并保留。

**`.srt`/`.txt`/`.vtt` 永不进「未标注」** —— 它们只在命中模式时才被收录,所以规则 5′ 必然先命中。「未标注」只装 `.md`。

### 3.1 权重

| 层 | 默认权重 |
| --- | --- |
| 你写的 | ×1.25 |
| AI 产出 | ×1.0 |
| 原始资料 | ×0.9 |
| 未标注 | **×0.3** |

×0.3 是刻意的强降权:配合默认只取前 20 条,未标注文件很可能被挤出结果集。**这个后果经用户确认接受**,理由是要形成「不标注就搜不到」的压力;配套出口是 `origin:unlabeled`(§6.3)。**不为未标注保留截断名额。**

## 4 · 收录范围

### 4.1 模式语义

`is_indexable` 改为:

```
.md                    → 一律收录(与模式无关)
.srt / .vtt / .txt     → 仅当命中原始资料模式时收录
其余扩展名             → 不收
```

所以同一份模式既决定「收多宽」也决定「算不算原始资料」,不需要额外开关:`ebook/**` 只框住一个目录,`**/*.srt` 就是全库通收。

**语法故意做窄**:只支持 `**`(跨层)、`*`(单层内)与字面段。不支持花括号展开、不支持正则。理由是这个串要给人看、要能从样例路径反推,语法越小越不会写错、生成器也越容易给出可预测的候选。

**大小写按字面匹配。** 本项目有过 vault 目录大小写被改掉的事故,所以设置页保存时若发现某条模式命中 0 个文件,当场提示(§7.2)。

**排除优先于收录**:`searchExcludeDirs` 命中的路径一律不收,与模式无关。

### 4.2 `.srt` / `.vtt` 解析

结构为「序号行 / 时间码行 / 文本行 / 空行」。索引只留**文本行**;序号与时间码剔除 —— 它们是噪声,`00:01:23,456` 这类串还会污染分词。`.vtt` 额外跳过 `WEBVTT` 头与可选的 cue 标识行。

**行号必须映射回原文件的真实行。** 剔除只影响进 FTS 的文本,不影响 `line_start`/`line_end`。输出给 agent 的是 `path#Lnnn`,一个自信但指错位置的引用比没有引用更糟 —— 这是整个检索设计里最不能破的契约。

**单条字幕不单独成块**:一条通常只有五到十个字,逐条成块会让块数暴涨,且跨条的句子永远匹配不上。做法是把连续字幕条**按目标字数合并**成块,`line_start` 取首条文本行、`line_end` 取末条文本行。

> **勘误(2026-08-12,C-T4 落地时发现,C-T12 回填进本文档)。** 本节原先写的是「目标字数**复用散文分块器已有的那个常量**,不新增一个」。**那个常量不存在**:`prose.rs` 按 markdown 结构切块(段落、标题、章节),根本不做按字数合并,其唯一的数字常量是面包屑的 40 字截断。C-T4 当时改了计划(见 plans 文件同名小节的「计划勘误」),但没回头改本文档,于是这条规范句一直是假的。
>
> 实际实现是转写分块器自己的常量 `transcript::TARGET_CHARS = 200`(按 `chars()` 计,不是字节 —— 语料以中文为主,一个汉字 3 字节但仍是一个意义单位),理由写在该常量的文档注释里:200 与一个散文段落是同一量级,小到 `#Lnnn` 锚点仍然精确、大到 bm25 不会被一堆碎块虚高;而单条字幕只有五到十个字,不合并就永远匹配不上跨条的句子——那正是收录转写稿的主要动机。`plain.rs`(`.txt`)不合并,按空行分段即可,所以不需要这个常量。
>
> 原句的顾虑(两个分块器粒度不一致会让同一句话在 `.md` 与 `.srt` 里可检索性不同)本身仍然成立,只是不能靠「复用一个不存在的常量」来消除;能消除它的是把 200 定在散文段落的量级上,这也正是上面选值的依据。

面包屑无标题可用,填文件标题。

### 4.3 `.txt` 解析

按**空行分段**成块,行号取段落首行,面包屑填文件标题。

### 4.4 体积

既有的索引占用实测只覆盖 `.md`。转写文本量大,实施计划中须在真实 vault 上单独测一次增量,并据此决定索引大文件阈值(现 10 MB,已与 git 门禁解耦)的默认值是否要调。

## 5 · 迁移与失效

### 5.1 Schema bump 2 → 3

`origin` 多了 `unlabeled` 取值,`files.ext` 多了 `srt`/`vtt`/`txt`,旧库的分层结论全部作废。按既有设计走**删旧重建**,不写迁移脚本。

这是 v6.812.1 之后的第二次强制重建,因此**本项目合入 main 后不单独发版**,与下一个功能一并生效。

### 5.2 默认模式的种子

首次升级时若模式列表为空,用**当前解析出的 `syncDir`** 种一条 `<syncDir>/**` —— 不是字面量 `sync/**`。改过镜像目录名的用户否则会突然发现镜像文件不再算原始资料。

`syncDir` 设置本身保留(vault 同步仍在用),只是不再参与分层。

### 5.3 模式变更必须触发重建

`origin` 是**存储的派生值**,而增量扫描的 stat/hash 快路径永远不会回头重算它 —— 这正是上一轮 `sync_dir` 踩过的坑。解法复用既有机制:把模式列表的**规范化形式**盖章进 `meta`,不匹配时**原地重建**(`DELETE FROM` 四张表 + 重新盖章),**绝不 unlink** —— GUI 可能正握着活的 WAL 连接。

规范化形式须对「顺序不同、空白不同、尾斜杠不同但语义相同」的两份列表产生同一个串,否则会出现无谓的重建。

### 5.4 权重变更**不**触发重建

权重是**查询时**在 `score_of` 里应用的,`origin` 已存在库中。改权重下一次查询即生效,不重建。设置界面必须让这个差别可见(§7.3),否则用户会以为每调一个数字都要等十秒。

## 6 · 对外接口

### 6.1 权重的单一构造点

排序是核心 crate 行为,GUI / CLI / watcher 共用。`ScanOptions` 已有唯一构造点 `search::options::for_vault` 与契约测试 `search_scan_options_contract.rs` 挡住第二个构造点;权重照抄这套 —— 否则 GUI 与 `notemd search` 会对同一个 vault 给出不同排序,「一个算法三个 adapter」的前提就破了。

`Weights` 是独立结构,不并进 `Limits`(那是预算与中止,语义不同)。`Weights::default()` **必须**等于 §3.1 的四个数,并有测试钉住 —— 前车之鉴是 `Limits::default()` 的 `deep: false` 与该类型自己的向后兼容承诺相反,一个未来的 `..Default::default()` 会静默拿到快路径。默认值方向必须落在安全的一侧。

**校验**:只接受有限正数;拒绝 NaN、负数与零(零会让整层分数塌成 0,排序退化成不确定)。上限护栏 5.0。允许用户把「原始资料」调得高于「你写的」—— 那是他自己的 vault。

### 6.2 回归集钉死默认权重

57 条 retrievability 用例是唯一的排序裁判。它们**必须显式使用 `Weights::default()`**;若跟随用户配置,等于没有裁判。

### 6.3 过滤器与分组

`origin:` 增加第四个值 `origin:unlabeled`。

分组顺序:**你写的 → AI 产出(按类型细分)→ 原始资料 → 未标注**。

**必须同步更新 `agents_sync` 的 `SEARCH_SECTION`** —— 那是写进每个 vault 的 `AGENTS.md`、agent 学这套语法的唯一来源。它是 append-only 的、只在整段缺失时才写,所以漏了就是永久静默。上一轮评审专门抓过这个漏项。`cli/builtin.rs` 的 `--help` 同步。

CLI 默认输出仍逐字为 `path:line:text`;`--json` 的 `origin` 增加 `unlabeled` 取值;`--stats --json` 的分层计数增加该层。

## 7 · 设置界面

在「搜索与索引」页新增两块。

### 7.1 原始资料模式

模式列表,每条右侧实时显示命中文件数。

**命中数由后端命令按真实 vault 现场计算**,不是前端拿索引里的行数估的 —— 模式可能命中尚未进索引的 `.srt`/`.txt`(它们正是靠这条模式才会被收录),用索引反推会永远少算,而少算的方向恰好会诱导用户把模式写得更宽。

**「从样例路径生成」**:粘一条 vault 内路径,给出**从窄到宽的候选**并各自标注命中数:

```
ebook/三体/**          12 个文件
ebook/**/*.md          340 个文件
ebook/**             1,204 个文件   ← 含 srt/txt
```

**默认选中最窄的一条。** 写窄了用户会立刻发现少东西并去放宽;写宽了却可能几千个文件悄悄进索引而不自知。

### 7.2 命中 0 个的提示

保存时若某条模式命中 0 个文件,当场提示。这是大小写字面匹配(§4.1)的兜底。

### 7.3 权重

四个数字输入,标签与分层一致,配「恢复默认」。旁注必须写明:**改权重立即生效,不重建索引**;而改模式会触发一次重建。

### 7.4 分层统计

从三层改为四层。**「未标注」那一行做成可点的行动项** —— 点击即在搜索面板执行 `origin:unlabeled`,列出所有该补 frontmatter 的文件。这是 ×0.3 的配套出口:降权是压力,这里是出口。

## 8 · 错误与降级

| 情况 | 行为 |
| --- | --- |
| 模式串语法非法 | 保存时拒绝并指出位置;已存的模式不受影响 |
| 模式命中 0 个文件 | 允许保存,但提示(§7.2) |
| 权重非法(NaN/负/零/超上限) | 保存时拒绝,保留原值 |
| `.srt` 时间码格式异常 | 该行按普通文本收录,不报错(容忍义务) |
| `.txt` 是二进制误命名 | 走既有的大文件/非文本跳过路径,记入被跳过清单 |
| 模式盖章不匹配 | 原地重建,记一行 `search` 分类日志 |

## 9 · 测试

**Rust**
- 规则表:5′/6′ 各自的正反用例;5′ 与 2/4 的顺序用例(改名保留既有那条)
- 模式匹配:`**` 跨层、`*` 不跨层、字面段、前缀相似不误命中(`ebook2/` 不被 `ebook/**` 命中)、空模式不匹配一切

- `.srt`:跨条句子能被单次查询命中
- `.txt`:空行分段,行号取段落首行
- `Weights::default()` == §3.1 四个常量
- 四档权重**逐档单独** mutation 验证 —— 前置项目出现过「两个乘数同向、任一失效测试仍绿」的假阴性

- 深浅色主题

## 10 · 残余风险

- **×0.3 会让大量既有笔记从搜索里消失。** 多数 vault 现状是大部分文件没有 frontmatter。这是经确认接受的强制力设计,出口是 `origin:unlabeled`;但上线首日的观感冲击是真实的,release note 必须正面说明。
- **模式是字面大小写匹配。** vault 目录大小写被改过就会全部落空,靠命中 0 个的提示兜底,不是零风险。
- **转写收录后的索引体积未知。** §4.4 要求实测,但真实 vault 的分布可能与测量样本差异很大。
- **规则 2 先于 5′ 的已知盲区仍在**(见 `origin.rs` 规则 2 注释):一个给 `type: Book` 补了 `generated:` 戳的转换流水线,会把电子书从原始资料层移走。本次不改顺序 —— 顺序是规范性的,要改得连 spec 一起改。
